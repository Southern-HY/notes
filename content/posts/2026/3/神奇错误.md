今天重新做了次力扣 5. 最长回文子串，代码是这样的：

```C++ hl_lines="14 15 16 22 46"
class Solution {
public:
    string longestPalindrome(string s) {
        if (s.size() == 0 || s.size() == 1) {
            return s;
        }
        if (s.size() == 2) {
            if (s[0] == s[1]) return s;
            else {
                return s.substr(0, 1);
            }
        }

        int start;
        int end;
        int max_l = 1;

        bool record[1001][1001];

        for (int l = 1; l <= s.size(); l++) {
            for (int i = 0, j = l-1; j < s.size(); i++, j++) {
                printf("%d %d\n", i, j);
                if (l == 1) {
                    record[i][j] = true;
                } else if (l == 2) {
                    if (s[i] == s[j])
                        record[i][j] = true;
                    else
                        record[i][j] = false;
                } else {
                    if (record[i+1][j-1] && s[i] == s[j])
                        record[i][j] = true;
                    else
                        record[i][j] = false;
                }
                if (record[i][j] == true) {
                    if (l > max_l) {
                        start = i;
                        end = j;
                        max_l = l;
                    }
                }
            }
        }

        return s.substr(start, max_l);
    }
};
```

我发现，现在代码能正常运行，但是如果去掉调试用的`printf`语句，居然会报错

```
terminate called after throwing an instance of 'std::out_of_range'
what():  basic_string::substr: __pos (which is 434635525) > this->size() (which is 5)
```

原因是，

- 上面的`start`、`end`变量没有赋初始值
- 而`printf`是一个IO操作，阻止了编译器的优化，可能导致内存布局略有不同，或者编译器生成的代码在栈上保留了更多空间，总之start在内存中的初始值恰好是0
- 去掉`printf`后，编译器的优化策略改变，导致`start`的初始值是一个垃圾值（比如434635525）
- 又遇上了像“abcda”这样整个循环中没有对`start`、`end`造成任何新赋值的输入

最后返回时执行`return s.substr(434635525, 1);`然后就访问越界了。
